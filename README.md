# Эфир

Веб-приложение для трансляции экрана, окна приложения или вкладки через **LiveKit SFU**. Go API и React/TypeScript интерфейс. Без регистрации: один ведущий и до 10 зрителей в комнате. Медиа всегда проходит через сервер.

## Запуск

Нужен Docker с Compose (на Windows/macOS — запущенный Docker Desktop в режиме Linux containers).

```sh
docker compose up --build -d
```

Откройте **http://localhost**, создайте комнату, выберите источник и отправьте зрителям ссылку из панели «Позовите своих». Первый запуск скачивает образы и собирает клиент и сервер. Готовность: `docker compose ps`; журналы: `docker compose logs -f`. Остановить: `docker compose down`.

Локальная конфигурация предназначена для браузеров на том же компьютере. Ссылка localhost не работает на чужом компьютере. Для доступа из интернета настройте домен и публичный IP по инструкции ниже.

## Возможности

- Отдельные ссылки ведущего (с секретом во fragment `#key=`) и зрителя.
- Экран, окно или вкладка выбираются в системном диалоге браузера.
- Разрешения: Авто (до 4K), 720p, 1080p, 1440p, 2160p. Независимый выбор 30/60 FPS, в том числе во время эфира.
- Битрейт автоматически подбирается от 2.5 до 25 Мбит/с. 4K60 — желаемое качество: реальное зависит от исходного изображения, компьютера, кодировщика и канала. Соотношение сторон сохраняет браузер.
- В студии отдельно отображаются настройки захвата и текущие разрешение/FPS кодируемого исходящего потока из WebRTC stats. Для неподвижного экрана фактический FPS может быть меньше выбранного.
- Звук выбранного источника, если браузер предлагает его захват. Отдельный регулятор громкости и mute у каждого зрителя. Превью ведущего всегда muted.
- Полноэкранный просмотр, вписывание/заполнение, ожидание эфира, переподключение и завершение.

Основной сценарий ведущего: актуальный Chrome/Edge на компьютере. Зритель может использовать мобильный браузер. Захват системного звука зависит от ОС и типа поверхности; если звук не предложен или не выбран в системном диалоге, приложение не может добавить его самостоятельно. Микрофон не захватывается.

Игры можно транслировать через окно или монитор, если браузер захватывает их изображение. При чёрном кадре переключите игру в оконный режим без рамки или выберите весь монитор. Захват exclusive fullscreen и защищённого видео не гарантируется. Это браузерный screen capture, специального драйвера захвата игр нет.

## Развёртывание в интернете

1. Направьте DNS A-запись своего домена на IPv4 сервера.
2. Скопируйте `.env.example` в `.env` и заполните `APP_URL`, `SITE_ADDRESS`, `LIVEKIT_URL`, `LIVEKIT_NODE_IP`, случайный API key и секрет длиной минимум 32 символа. Секрет передаётся только контейнерам Go и LiveKit.
3. Откройте/пробросьте **80/TCP, 443/TCP, 7881/TCP, 50000–50050/UDP** на Docker-хост. Укажите его публичный IP, а не адрес контейнера, в `LIVEKIT_NODE_IP`. WebSocket идёт через Caddy, медиа — непосредственно в LiveKit по опубликованным портам.
4. Запустите ту же команду `docker compose up --build -d`. Caddy автоматически получает HTTPS-сертификат. HTTP вне localhost не подходит для захвата экрана.

При работе в LAN используйте доступное всем клиентам имя с доверенным HTTPS и IP Docker-хоста. Если внешний домен применяется внутри той же LAN, маршрутизатору может требоваться NAT loopback.

По умолчанию есть UDP и ICE/TCP fallback. TURN/TLS не включён: в корпоративных сетях, разрешающих только HTTPS на 443, соединение может не установиться. Для таких сетей нужен отдельный TURN/TLS endpoint и соответствующая конфигурация LiveKit. Обычный HTTP reverse proxy не заменяет TURN.

Для 4K60 при лимите 25 Мбит/с ведущему нужен достаточный upload, а серверу — до 250 Мбит/с исходящего трафика на 10 зрителей, плюс накладные расходы. Это расчёт по установленному потолку, а не результат нагрузочного теста. Сервер пересылает поток и не выполняет перекодирование; отдельные разрешения для каждого зрителя в эту версию не входят.

## Жизненный цикл и доступ

Go хранит комнаты в памяти; один экземпляр API на отдельный экземпляр LiveKit. После рестарта комнаты завершаются. При запуске API удаляет старые комнаты с префиксом `broadcast-` в этом LiveKit. Не запускайте несколько копий API против одного LiveKit.

Неиспользованная комната живёт 30 минут. После исчезновения ведущего предусмотрено 45 секунд на переподключение; затем SFU-комната удаляется, а страница ещё 10 минут сообщает о завершении. Явная кнопка завершения или остановка захвата закрывает эфир сразу. API сверяет состояние с LiveKit каждые 3 секунды, без зависимости от webhook.

Права зрителя запрещают публикацию аудио, видео и data packets. Ведущему разрешены только screen-share источники; фиксированная identity гарантирует одного ведущего (новая сессия студии отключает старую). Токен подключения действует 60 секунд; LiveKit поддерживает уже установленную сессию. Комнаты не создаются автоматически по старому токену: `auto_create: false`. Выданное зрителю место резервируется на 90 секунд и продлевается, пока участник присутствует. Это ограничивает гонки при одновременном входе; после ухода место освобождается не мгновенно.

Ссылка ведущего даёт право управления: не пересылайте её зрителям. Публичный список комнат отсутствует, но любой обладатель ссылки просмотра может войти. Это доступ по ссылке, не end-to-end encryption: сервер имеет доступ к медиапотоку. HTTP/API защищены same-origin проверкой и простым IP rate limit; публичный сервис большого масштаба потребует отдельной защиты от злоупотреблений.

## Разработка и проверки

```sh
go test ./...
go vet ./...
cd web
corepack enable
pnpm install --frozen-lockfile
pnpm test
pnpm run build
pnpm test:e2e
```

Go 1.26+, Node 24+, pnpm 11.19.0. Production Docker build выполняет Go tests/vet, тесты качества и TypeScript build. Сквозные тесты запускаются отдельно при работающем `docker compose up`: на Windows используется установленный Edge, на других ОС установите Chromium командой `pnpm exec playwright install chromium`. Для frontend development `pnpm dev` проксирует `/api` на Go `localhost:8080`; при отдельном запуске Go задайте `APP_URL` под origin dev-сервера и доступные LiveKit URLs.

Проверено 17.09.2026: Go tests/vet, четыре теста качества, production build, Docker Compose; в Edge — публикация видео и аудио через настоящий SFU, регулировка громкости/mute, смена настроек качества, приём видео десятью отдельными зрительскими сессиями, отказ одиннадцатому и завершение комнаты. Проверена мобильная вёрстка 390 px и ошибка отсутствующей комнаты. Только источник захвата в автоматическом тесте заменён canvas-видео и генерируемым аудио; проверка реальных игр и стабильных 4K60 остаётся аппаратно-зависимой ручной проверкой.

Структура: `cmd/server` — запуск, `internal/broadcast` — API и LiveKit RoomService, `web/src` — клиент, `deploy` — LiveKit/Caddy. REST API: создание `POST /api/rooms`, состояние `GET /api/rooms/{id}`, токены `POST .../host-token` и `.../viewer-token`, завершение `POST .../end`. Host-запросы принимают `{ "hostSecret": "..." }`; viewer-запросы `{ "session": "..." }`, с пустой строкой при первом входе.

Ссылки на протоколы: [LiveKit deployment](https://docs.livekit.io/transport/self-hosting/deployment/), [Screen Capture API](https://www.w3.org/TR/screen-capture/).
