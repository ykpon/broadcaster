# План реализации Broadcast

Согласованная цель: Go API + React, LiveKit SFU, комнаты без регистрации, 10 зрителей, разрешение до 4K и отдельный выбор 30/60 FPS, громкость зрителя, Docker Compose.

1. Реализовать Go API и клиент LiveKit RoomService: генерация секретов, ограниченные grants, комнаты, 10 мест с резервированием на время входа, завершение, очистка и rate limit. Проверить HTTP-тестами с тестовым медиасервером, включая подпись JWT и права зрителя.
2. Реализовать React-клиент: создание, студия, просмотр, реальный screen capture, управление разрешением/FPS, звук, состояние соединения и очистка треков. Проверить функции качества и production TypeScript build.
3. Собрать Dockerfile, Compose и локальную/публичную конфигурацию для существующего Nginx на хосте. Написать README с HTTPS, WebSocket, сетевыми портами, ограничениями capture и эксплуатацией.
4. Выполнить Go test/vet, тесты и сборку клиента, Compose validation, браузерную проверку. Отдельно указать непроверенные сценарии реального WebRTC/4K60.

Файлы: cmd/server/main.go (запуск), internal/broadcast/{media,server}.go (медиа API и комнаты), соответствующие *_test.go, web/src/{App,media,quality,api,styles} (интерфейс), Dockerfile, compose.yaml, deploy/nginx.conf.example, README.md.

Уточнение реализации: вместо зависимости от доставки webhook используется регулярная сверка ListParticipants с LiveKit, с 45-секундным grace period ведущего; настройки трека и измеренная скорость кодирования выводятся раздельно. Комнаты ожидания истекают через 30 минут, завершённые хранятся ещё 10 минут. При перезапуске API пространство имён комнат меняется; orphan-комнаты удаляются при следующем запуске.
